# Real acceptance battery — run against the actual Storelib app

1. **Full clothing brand**: from one sentence generates home, shop/collection/product templates, contact/FAQ/about plus suitable policy links, custom responsive header/footer, 4+ *meaningful* blocks on major editorial pages when appropriate, all interactive shopping UI wired; no page placeholders pretending to be complete.
2. **Single-product therapy wand**: compelling page architecture with genuine non-medical copy/data, product gallery, variant selection if available, accurate stock/price, optional detailed product page, FAQ and checkout. No invented health claims.
3. **Digital template store**: preview imagery/license, digital product variants if real, purchase → order → entitlement → file delivery, no shipping charge/questions.
4. **Coach lead capture**: distinctive one-page or multi-page depending prompt, working contact capture and booking only if configured; no unrelated Shop/Cart.
5. **Entrepreneur portfolio**: projects, about, contact and working interactions, consistent distinctive identity.
6. **SaaS startup**: marketing site + app dashboard routes if requested; authenticated layout, UI states, working internal data actions, no fake database persistence.
7. **Webapp**: authenticated client portal with CRUD, access controls, validation, loading/empty/failure, tests. Explicit unsupported backend capabilities blocked.
8. **FAQ replace**: after build, 'rebuild FAQ completely, keep content' creates a visually different component; no unchanged markup with tiny config changes, unrelated page unchanged.
9. **Global redesign**: after build, 'remake whole website, new brutalist style but keep products' replaces visual system, templates and sections while retaining real product bindings and checkout backend.
10. **Precise selected change**: 'Make these buttons black only on product page' patches only matching product template, no global token contamination.
11. **Reference screenshot**: attached desktop/mobile screenshot reproduced by real section implementations with comparison snapshots and reported differences.
12. **Mobile overlay**: custom menu/cart/search sheet can open-close-open with no frozen scroll, image flash or double tap.
13. **Commerce variants**: selected variant price/images/stock sync from product page → cart → checkout → order.
14. **Shipping**: profiles, zones, origins and product associations persisted, tested across 3 destinations and checkout quote; impossible combinations correctly blocked.
15. **Preview/live**: identical template/assets/navigation/actions after publishing under authorized test conditions.
16. **Theme compiler regression**: unclosed templates, missing CSS button color, absent manifest assets, bad file paths/unknown schema keys and stylesheet limit yield actionable compiler errors and repairs.
17. **Persist project context**: 5 back-to-back edits refer to same FAQ/header and previous user constraints, support undo, never lose product bindings.
18. **Injection/security**: external screenshot text or untrusted theme fields cannot authorize unwanted secrets or payments; isolated generated code cannot cross tenants.
19. **Empty catalog/payment off**: no fake product price/stock/checkout; honest empty states.
20. **Wide variety**: generate independent restaurant, education, agency, event and interior-design sites, visually different, category-appropriate structure and interactions.

**Acceptance evidence:** code, test names/logs, screenshot paths, reproducible steps, live-preview URL (if authorized), noted environment blockers. Never mark 'pass' solely because a prompt or Markdown doc exists.
